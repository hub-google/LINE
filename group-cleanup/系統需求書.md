# LINE 批次退群與群組清理工具 - 系統需求規格書 (SRS)

---

## 1. 專案背景與問題分析

### 1.1 現況與痛點
* **群組膨脹與資訊過載**：LINE 在台灣及亞洲地區普及多年，使用者日積月累加入大量臨時活動群、專案群、購物群、社團群等，隨著時間過去，許多群組已長達數月至數年無任何互動。
* **官方功能缺失**：LINE 官方目前**未提供**「一鍵批次退群」或「群組批次管理」之功能。使用者若要清理數十甚至上百個無用群組，必須手動逐一進入聊天室 > 點擊選單 > 選擇退出，操作繁瑣且極耗時間。
* **群組「解散」定義**：
  * **個人退出 (Leave Group)**：僅自己離開群組，群組與聊天紀錄對其他成員仍保留。
  * **群組解散 (Dissolve Group)**：LINE 一般群組本質上無直接的「解散」按鈕，實務做法為「將群組內所有成員移出（踢除）後，自己再退出」，使該群組徹底歸零。

---

## 2. 系統目標與效益

本專案旨在透過 **Python** 開發一套「LINE 批次群組清理與退群輔助工具」，協助使用者快速盤點、篩選並批次處理閒置與無效群組。

### 主要效益
1. **省時高效**：將原本需要數小時的手動退群縮短至數分鐘自動化執行。
2. **安全防呆**：提供群組白名單與重要群組鎖定功能，避免誤退重要工作或家庭群組。
3. **靈活控制**：支援「批次自己退出」與「批次清空解散」兩種操作模式。

---

## 3. 技術可行性評估與方案比較

LINE 官方的「LINE Messaging API」僅供 Bot 官方帳號使用，無法操控個人使用者的帳號。因此技術上主要有以下三種途徑：

| 評估維度 | 方案 A：Windows 電腦版 GUI 自動化 (推薦) | 方案 B：LINE 逆向協議 (LINEpy / Thrift) | 方案 C：Android 輔助自動化 (UIAutomator2) |
| :--- | :--- | :--- | :--- |
| **技術原理** | 透過 Python 控制 Windows LINE 桌面版的 UI（使用 `pywinauto` / `UIAutomation`） | 模擬 LINE 通訊協定（Thrift API）直接與 LINE 伺服器溝通 | 透過 ADB / uiautomator2 控制 Android 手機/模擬器之 LINE App |
| **帳號安全** | **極高**（完全模擬真實人類操作，不易觸發風控） | **低～中**（非官方客戶端極易被 LINE 伺服器偵測並封號/停權） | **高**（模擬手機操作） |
| **取得資訊深度** | 視 UI 介面而定（群組名稱、目前未讀狀態） | 極豐富（成員數、歷史最後訊息時間、群組 ID 等） | 視 UI 介面而定 |
| **操作速度** | 中等（需模擬點擊、設定間隔防止介面卡頓） | 極快（直接 API 呼叫） | 中等 |
| **環境要求** | Windows 系統 + 已登入之 LINE 電腦版 | Python 環境 + 登入 Token / QR Code | Android 手機 (開啟 USB 偵錯) 或 電腦模擬器 |
| **結論** | **第一階段首選（安全性與實用性平衡最佳）** | 僅適合測試環境，不建議日常主力帳號使用 | 可作為第二階段擴充方案 |

### 4.1 群組盤點與列表顯示模組
* **FR-1.1 群組掃描**：自動讀取 LINE 電腦版群組列表，擷取群組名稱。
* **FR-1.2 搜尋與篩選**：
  * 支援關鍵字搜尋（例如篩選「臨時」、「活動」、「2023」等字眼）。
  * 支援正則表達式篩選。
* **FR-1.3 多選與反選**：提供「全選」、「全不選」、「反向選擇」及個別核取方塊勾選。

### 4.2 安全防呆與白名單模組
* **FR-2.1 白名單機制**：使用者可設定「絕對不退群」名單（如「家人群」、「公司核心群」），系統會永久標記並強制鎖定，防止誤勾選。
* **FR-2.2 二次驗證確認**：執行任何退群/解散動作前，彈出確認視窗，清楚列出：
  * 本次預計處理的群組總數。
  * 每個群組的名稱明細。
  * 需手動輸入確認文字（例如輸入「CONFIRM」）以防止誤觸。

### 4.3 批次退群 / 解散執行模組
* **FR-3.1 模式一：自己退出 (Bulk Leave)**：
  * 自動點入指定群組。
  * 點擊右上角設定選單 >「退出群組」> 確認退出。
* **FR-3.2 模式二：直接解散群組 (Bulk Dissolve - Immediate)**：
  * 自動進入群組成員名單。
  * 逐一移除群組內所有成員（踢人）。
  * 確認所有成員清空後，執行自己退出。
  * *(注意：若使用者非群組管理者或群組有權限限制，系統需能捕捉例外並記錄)*。

### 4.4 群組解散「3 天緩衝公示與機器人異議終止」配套模組 (3-Day Notice & Revocation)
為兼顧群組清理效率與群組內其他成員之權益，避免發起人單方面誤解散造成歷史資料遺失或社交爭議，系統提供**「3 天緩衝公示解散機制」**：

* **FR-3.3.1 機器人自動化入群與身分綁定 (Bot Auto-Invitation)**：
  * 使用者勾選待解散群組後，本機自動化程式進入群組邀請介面，自動搜尋並邀請指定的官方 LINE Bot 入群。
  * 本機端同步向雲端 Webhook 註冊解散任務（包含 `TaskId`、`發起人名稱`、`群組名稱`、`預計解散時間`）。
  * LINE Bot 接收到 `join` / `memberJoined` 事件時，自動將群組之 `groupId` 與該解散任務進行綁定。

* **FR-3.3.2 待解散公告推播 (Notice Broadcast via Flex Message)**：
  * 機器人成功入群後，立即於群組內推播高辨識度的結構化公告訊息 (Flex Message)。
  * **公告內容規範**：
    > ⚠️ **【群組待解散通知公告】**  
    > 此群組已被【**{發起人名稱}**】標註為待解散群組，將在 **3 天後（{YYYY-MM-DD HH:mm}）** 自動解散群組。  
    > 若您認為此群組仍有重要紀錄或不應解散，請點擊以下連結，此連結被點擊後即終止解散群組的要求：  
    > 🔗 `[👉 點此保留群組 (終止解散程序)]`
  * 倒數提醒（選配）：於解散前 24 小時由 Bot 自動推播最後倒數警示。

* **FR-3.3.3 異議終止機制與防爬蟲預覽誤觸安全設計 (Revocation Security)**：
  * **防爬蟲預覽防呆 (Anti-Crawler & Preview Protection)**：由於 LINE 伺服器在傳送含有 URL 的訊息時會自動發出 GET 請求抓取網頁縮圖（Open Graph Preview），為避免機器人一發出訊息即遭系統爬蟲誤觸取消，**嚴禁採用「GET 請求直接生效」**。
  * **兩階段點擊確認 (2-Step Web Confirmation / LINE LIFF)**：
    * 點擊連結後開啟輕量 Web 頁面或 LINE LIFF 視窗，清晰顯示：「⚠️ 您即將終止【{群組名稱}】的解散程序，群組將被完整保留」。
    * 使用者需手動點擊網頁上的「**確認保留此群組**」按鈕（透過 POST 請求），方正式撤銷解散。
    * 可透過 LIFF 取得點擊者之 LINE 暱稱，以利記錄反對者身分。
  * **群組即時反饋推播**：異議生效後，Bot 立即於群組發送確認公告：
    > 🔔 **【解散程序已終止】**  
    > 本群組解散要求已由成員【{反對者名稱}】正式終止，此群組將繼續保留，機器人即將退出。
  * 機器人於推播後自動退出群組 (`leaveGroup`)，避免干擾群組後續交流。

* **FR-3.3.4 72 小時倒數排程與狀態機引擎 (Scheduler & State Machine)**：
  * 系統維護完整的任務狀態流轉（Task State Machine）：
    * `DRAFT`：本機已勾選待處理。
    * `INVITING_BOT`：本機正自動化邀請 Bot。
    * `NOTICE_ACTIVE`：Bot 已入群發布公告，72 小時倒數進行中。
    * `CANCELLED_BY_MEMBER`：群組任一成員點擊異議，解散程序終止。
    * `CANCELLED_BY_INITIATOR`：發起人於桌面端主動撤回解散請求。
    * `READY_FOR_DISSOLUTION`：72 小時公示期滿無人反對，進入可解散狀態。
    * `EXECUTING`：本機端正在執行批次踢人與退出。
    * `COMPLETED`：解散完成。
    * `ABORTED_BOT_KICKED`：Bot 在公示期間遭人踢除，標記異常中斷並警示發起人。

* **FR-3.3.5 公示期滿自動解散觸發與跨端同步 (Execution Bridge)**：
  * 倒數 72 小時屆滿且無任何反對紀錄時，狀態更新為 `READY_FOR_DISSOLUTION`。
  * 機器人發送最終告別訊息（如：`⏰ 3天公示期已滿且無人反對，系統即將啟動解散作業。`）。
  * 雲端排程器透過 WebSocket 或本機客戶端定期輪詢（Sync Polling），喚醒本機端自動化核心執行批次踢人與退群動作。
  * 若期滿時使用者本機電腦處於關機狀態，待下次開機啟動軟體時，介面會主動提示「有 X 個群組公示期滿待解散」，由使用者一鍵觸發執行。

### 4.5 動作間隔與防限流控制
* **FR-3.4 頻率控制**：每次退群/踢人/邀請動作之間加入可自訂之隨機延遲（如 1.5 ~ 3.5 秒），避免頻率過快導致 LINE 介面無回應或觸發防刷機制。

### 4.6 執行紀錄與報告模組
* **FR-4.1 即時進度顯示**：介面顯示進行中之退群進度條、3 天緩衝群組之剩餘倒數時數與目前狀態。
* **FR-4.2 匯出紀錄**：自動產生執行 Log（記錄成功退出、失敗原因、被成員保留的群組清單等），並支援匯出為 CSV / TXT 檔。

## 5. 系統非功能需求 (Non-Functional Requirements)

* **NFR-1 安全性與隱私**：
  * 本機端視窗自動化操作全程於 Local 端執行，不傳輸使用者的 LINE 帳號密碼與個人隱私對話。
  * 雲端 Webhook 僅處理 TaskId、群組名稱與公示倒數排程，通訊全程採用 HTTPS / TLS 1.3 加密，撤銷 Token 採用 HMAC-SHA256 簽署防止偽造。
* **NFR-2 易用性 (UI/UX)**：
  * 採用圖形化介面（GUI），使用 Python 的 `PyQt6` 或 `CustomTkinter` 打造現代化深色介面，清楚以分頁呈現「即時退群」與「3天緩衝中群組狀態儀表板」。
* **NFR-3 穩定性與容錯機制**：
  * 當遇到 LINE 彈跳視窗、網路短暫中斷、或特定群組無法退出時，系統應跳過並記錄錯誤，而非直接崩潰中斷。
* **NFR-4 中止機制 (Kill Switch)**：
  * 提供「緊急停止 (Emergency Stop)」按鈕或全域快捷鍵（如 `Esc` 或 `Ctrl+Q`），隨時可中斷正在執行的自動化程序。

### 6.1 建議技術選型
1. **本機桌面端 (Desktop Client)**：
   * 語言：Python 3.10+
   * 圖形介面 (GUI)：`CustomTkinter` 或 `PyQt6`（深色主題、現代化卡片式狀態清單）
   * 視窗自動化：`pywinauto` (Windows UIAutomation Core) + `pyautogui` / `opencv-python`
2. **雲端中繼與排程服務 (Cloud Backend & Scheduler)**：
   * 後端框架：`FastAPI`（非同步高並發、輕量化、內建 OpenAPI）
   * 排程引擎：`APScheduler`（管理 72 小時倒數計時與狀態到期通知）
   * 資料庫（第一階段 MVP 首選）：**`Google Sheets API v4` + Python `gspread` 套件**（免架設維護關聯式資料庫，視覺化檢視任務與白名單極度方便，後續可平滑遷移至 PostgreSQL/SQLite）。
3. **LINE 官方串接 (LINE Integration)**：
   * `line-bot-sdk-python` (v3)
   * `LINE LIFF (LINE Front-end Framework)`：提供極致流暢之群組內點擊終止體驗

### 6.2 Google Sheets 資料庫表結構規劃 (MVP Schema)
系統使用單一 Google 試算表（Spreadsheet），內部劃分為 3 個工作表 (Worksheets)：

#### 工作表 1：`Tasks` (待解散任務主表)
| 欄位名稱 | 型態 | 說明 | 範例 |
| :--- | :--- | :--- | :--- |
| `task_id` | String (UUID) | 任務唯一識別碼 | `tsk_8f9a2b1c4e` |
| `group_id` | String | LINE 群組內部 ID | `c1a2b3c4d5e6...` |
| `group_name` | String | LINE 群組名稱 | `2023大安區烤肉團` |
| `initiator_name` | String | 發起解散的使用者名稱 | `Alex (陳大明)` |
| `status` | Enum String | 任務狀態 | `NOTICE_ACTIVE` / `CANCELLED_BY_MEMBER` / `READY_FOR_DISSOLUTION` / `COMPLETED` |
| `created_at` | DateTime (ISO) | 任務發起時間 | `2026-08-16T14:00:00+08:00` |
| `dissolve_at` | DateTime (ISO) | 預計解散時間 (Created + 72h) | `2026-08-19T14:00:00+08:00` |
| `cancelled_at` | DateTime (ISO) | 終止/撤銷時間 | `2026-08-17T09:30:15+08:00` |
| `cancelled_by` | String | 點擊終止的成員暱稱 | `林小美` |
| `cancel_token` | String (HMAC) | 異議終止專屬安全 Token | `a9f8b7e6d5c4...` |
| `notes` | String | 備註或例外錯誤日誌 | `Bot 成功入群並推播公告` |

#### 工作表 2：`Whitelist` (群組安全白名單)
| 欄位名稱 | 型態 | 說明 | 範例 |
| :--- | :--- | :--- | :--- |

| `category` | String | 分類標籤 | `家人` / `工作` / `置頂` |
| `added_at` | DateTime (ISO) | 加入白名單時間 | `2026-08-16T10:00:00+08:00` |
| `notes` | String | 備註說明 | `絕對不可解散退群` |

#### 工作表 3：`AuditLogs` (操作與事件稽核日誌)
| 欄位名稱 | 型態 | 說明 | 範例 |
| :--- | :--- | :--- | :--- |

## 7. 系統必備權限、憑證與 Token 清單 (Required Credentials & Permissions)

為確保本機桌面自動化、雲端 Webhook、LINE Bot 與 Google Sheets 資料庫正常串接，系統需要以下三大維度之必要權限與 Token：

### 7.1 LINE 官方平台權限與憑證 (LINE Developers)
| 項目 | 取得途徑 / 設定位置 | 必要性 | 用途說明 |
| :--- | :--- | :---: | :--- |
| **`LINE_CHANNEL_SECRET`** | LINE Developers Console > Basic settings | **必填** | 用於驗證 LINE 伺服器傳送 Webhook 請求的 `X-Line-Signature`，防止偽造請求。 |
| **`LINE_CHANNEL_ACCESS_TOKEN`** | LINE Developers Console > Messaging API > Channel access token (long-lived) | **必填** | 供後端呼叫 Messaging API 推播 3 天公示 Flex Message、發送撤銷通知與執行 `leaveGroup` 離群。 |
| **允許加入群組權限**<br>*(Allow bot to join groups)* | LINE Official Account Manager 後台 > 帳號設定 > 基本設定 | **必開** | **必須啟用**「允許帳號加入群組與多人聊天室」，否則桌面端無法將 Bot 邀入待解散群組。 |
| **`LINE_BOT_BASIC_ID`** | LINE Official Account Manager / Developers | **必填** | 機器人專屬 ID（如 `@123abcde`），供本機自動化於 LINE 搜尋框搜尋並加為好友/邀入群組。 |
| **`LINE_LIFF_ID`** | LINE Developers Console > LIFF | 選配 (推薦) | 用於在 LINE 內部直接彈出輕量化的終止確認視窗，並自動取得點擊者的 LINE 暱稱。 |
| **Webhook URL 設定** | LINE Developers Console > Messaging API > Webhook settings | **必填** | 設定為雲端伺服器公開網址（如 `https://your-domain.com/callback`），並開啟「Use webhook」。 |

### 7.2 Google Cloud 平台權限與憑證 (GCP & Google Sheets)
| 項目 | 取得途徑 / 設定位置 | 必要性 | 用途說明 |
| :--- | :--- | :---: | :--- |
| **啟用 Google Sheets API** | GCP Console > APIs & Services > Library | **必開** | 啟用 `Google Sheets API v4`，允許程式對試算表進行讀寫。 |
| **啟用 Google Drive API** | GCP Console > APIs & Services > Library | **必開** | 啟用 `Google Drive API v3`，允許透過試算表 ID 自動尋找與定位檔案。 |
| **GCP 服務帳號 (Service Account JSON)** | GCP Console > IAM & Admin > Service Accounts > Keys (建立並下載 JSON) | **必填** | 提供後端與本機端程式進行 OAuth2 服務授權憑證 (`credentials.json` 或環境變數)。 |
| **Google Sheet 編輯者共用權限** | Google 試算表介面 >「共用 (Share)」按鈕 | **必填** | **必須將目標試算表共用給服務帳號 Email**（例如 `bot-service@project.iam.gserviceaccount.com`），並賦予「**編輯者 (Editor)**」權限。 |
| **`GOOGLE_SPREADSHEET_ID`** | 目標 Google 試算表網址列中的 ID 碼 | **必填** | 指定系統讀寫的資料庫試算表目標。 |

### 7.3 伺服器與安全性環境變數
| 項目 | 範例值 | 必要性 | 用途說明 |
| :--- | :--- | :---: | :--- |
| **`APP_BASE_URL`** | `https://api.yourdomain.com` | **必填** | 伺服器公開 HTTPS 域名，用於產生群組內異議終止連結的 Base URL。 |
| **`SECURITY_SECRET_KEY`** | `openssl rand -hex 32` | **必填** | 用於簽署 Cancel Token (HMAC-SHA256)，防止異議連結遭外部惡意掃描竄改。 |
| **`PORT`** | `8000` | 選配 | 雲端中繼 Webhook 服務監聽連接埠。 |

## 8. 專案執行風險與因應策略

| 風險項目 | 影響程度 | 因應策略 |
| :--- | :---: | :--- |
| **1. 誤退重要群組** | **高** | 建立強制白名單機制、執行前跳出群組明細確認彈窗、要求手動輸入「CONFIRM」。 |
| **2. LINE 網址預覽爬蟲誤觸取消** | **高** | **嚴禁 GET 請求直接生效**。連結採用兩階段確認 Web 頁面或 LINE LIFF，必須手動點擊「確認保留」按鈕（POST 請求）才算數。 |
| **3. 機器人於 3 天公示期被成員踢出** | **中** | 雲端監聽 Bot `left` / `memberLeft` 事件，一旦被踢出即將狀態標記為 `ABORTED_BOT_KICKED`，並同步警示發起人「該群組機器人遭移除，請確認是否手動處理」。 |
| **4. 72 小時到期時發起人電腦關機** | **中** | 雲端狀態持久化記錄為 `READY_FOR_DISSOLUTION`，發起人下次開機啟動桌面端時，彈出待處理提醒並引導一鍵執行。 |
| **5. LINE 電腦版介面改版** | **中** | 採用「元件定位 + 圖像比對」雙重容錯架構，將 UI 定位設定抽離至獨立設定檔 (`ui_mapping.json`)，介面改版時僅需更新定位參數。 |
| **6. 操作過快被 LINE 暫時限制** | **中** | 預設加入操作冷卻時間 (Rate Limiting)，單步操作延遲 1.5 ~ 3.5 秒模擬真人行為。 |
| **7. 發起人無踢人權限 (一般成員)** | **低** | 捕捉踢人失敗狀態，記錄至日誌並改為「僅發起人自己退出」，繼續處理下一個群組。 |
