# Workforce 多企業、組織階層與權限驗收計畫

日期：2026-11-06  
站點：https://hub-google.github.io/LINE/workforce/  
程式：`tests/workforce-org-hierarchy-e2e.mjs`  
資料來源：真實 Supabase Auth + `wm_tenants`、`wm_members`、`wm_departments`、`wm_requests`、`wm_org_invites`，不以虛構前端陣列取代資料庫操作。

## 目標與權限模型

企業可以自行註冊帳號、建立獨立公司；由企業 Owner 建立部門、邀請員工，並指派直屬主管。每位員工僅能透過自己的 Auth UUID 加入公司；主管也有自己的 Auth UUID。每家公司有自己的 `tenant_id`，且同一使用者可加入多個企業。

| 身分 | 可查看人員 | 可以管理 | 審核範圍 |
|---|---|---|---|
| 企業總管理者 Owner | 本企業全員 | 企業、部門、主管鏈、邀請、權限 | 本企業其他人的申請 |
| HR 人資 | 本企業全員 | 除 Owner／HR 角色變更外的成員設定 | 本企業其他人的申請 |
| 部門主管 Manager | 自己＋管理鏈以下 | 授權下屬的排班 | 自己管理鏈以下的申請 |
| 組長 Manager（不同職稱） | 自己＋直屬及下屬 | 授權下屬的排班 | 直屬及下屬的申請 |
| 一般員工 Employee | 僅本人 | 本人打卡／請假／加班 | 不可審核 |
| 他企業 Owner | 自己的公司 | 僅另家公司的設定 | 不能查看或審核其他公司 |

*Owner／HR／Manager 都不可核准自己的申請。主管是否有權不取決於畫面按鈕，而由資料庫階層函式及 BEFORE UPDATE 審核守衛判斷。*

## 測試帳號與架構

**星河服務（完全虛構、公開測試資料）**
```text
陳總經理（Owner）
├─ 黃人資（HR）
├─ 王營運經理（Manager）
│  ├─ 林門市組長（Manager）
│  │  └─ 張一凡（Employee）
│  └─ 李小晴（Employee）
└─ 周客服主管（Manager）
   └─ 吳客服（Employee）
```

**海角工作室（獨立虛構公司）**
```text
蔡工作室負責人（Owner）
```

所有 QA 密碼僅用於虛構測試企業。禁止用此測試租戶儲存真實員工或營運資料。正式客戶應使用自己的 Email／密碼與專屬企業；企業邀請連結 7 日內、一次性、指定 Email 綁定，資料庫只保存 Token SHA-256。
